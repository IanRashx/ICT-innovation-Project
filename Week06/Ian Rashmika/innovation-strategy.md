# Week 6 – Innovation Strategy

**Project:** Agent Resilience – Attacking and Hardening LLM Agents on Commodity Hardware  
**Group:** LLM11  
**Member:** Ian Rashmika  
**Role:** Project Lead / Coordination

## 1. Innovation Classification

The project was considered against four innovation types: incremental, disruptive, radical, and architectural.

### Incremental Innovation

The project contains incremental elements because it improves existing AI security-testing approaches by combining attack testing, defensive evaluation, and measurable security assessment within a controlled workflow.

### Disruptive Innovation

The project is not considered primarily disruptive because it does not attempt to replace established AI security-testing technologies or introduce a new market.

### Radical Innovation

The project is not considered radical because it uses existing technologies and security concepts, including open-weight language models, adversarial testing, LoRA, and established AI security frameworks.

### Architectural Innovation

Architectural innovation best describes the project. Existing technologies and techniques are combined into a modular and offline security-testing architecture. The proposed workflow connects adversarial testing, AI models, resilience controls, evidence collection, and security evaluation.

The innovation is therefore primarily in the integration and application of existing components rather than the invention of a completely new AI model or attack technique.

## 2. Impact on Project Development

Classifying the project as architectural innovation changes the development focus toward:

- modularity;
- integration between components;
- reproducible testing;
- local execution;
- measurable security evaluation; and
- clear interfaces between attack, defence, and evaluation components.

The team will focus on developing components that can later operate within a common security-testing workflow.

## 3. Innovation Goals

### Goal 1 – Adversarial Testing

Develop a repeatable local workflow for evaluating AI-agent resilience against agreed adversarial and jailbreak prompts.

**Measure:** At least 80% jailbreak detection on the agreed evaluation dataset.

**Client relevance:** Allows AI security testing to be performed in a controlled environment without requiring sensitive testing data to be sent to external commercial services.

### Goal 2 – Benign Prompt Acceptance

Evaluate whether resilience controls maintain legitimate system usability.

**Measure:** At least 90% benign prompt acceptance during the agreed evaluation tests.

**Client relevance:** Security controls should reduce malicious behaviour without unnecessarily preventing legitimate research activity.

### Goal 3 – Reliable Evaluation

Develop a reproducible evaluation workflow for recording and comparing security-testing results.

**Measure:** At least 95% of planned evaluation test cases complete without application failure.

**Client relevance:** Reliable testing provides repeatable evidence that can support future AI security research.

## 4. Strategy to Technical Execution

The innovation strategy is translated into technical work through four main areas:

1. Controlled adversarial testing against small open-weight AI models.
2. Comparison of baseline and modified model behaviour.
3. Application and evaluation of resilience controls.
4. Collection of measurable security results.

The current model-layer work provides an initial experimental basis for this approach. Further components can be integrated into the common testing workflow as development progresses.
